# 미국 주식 데일리 후보 분석

미국 거래일 종가로 향후 20거래일 내 +10% 도달 후보를 찾는다.
데일리 스캔은 고정 목록 177종목, 학습은 335종목이다. `SP500`도 전체 지수가
아닌 120종목의 고정 목록이다. 자동 주문은 제출하지 않는다.

## 실행

Python 3.10 이상:

```sh
pip install -r requirements.txt
python surge_model.py train
python pattern_miner.py
python scheduled_scan.py --prepare
python daily_scan.py ALL  # 기존 예약 명령도 자동 모델 준비 경로를 사용
python -m unittest discover -s tests -v
```

기존 `surge_model.pkl`과 `pattern_rules.json`은 새 검증 방식으로 생성된 파일이
아니므로 사용하지 않는다. 기존 `python daily_scan.py ALL` 명령은 `scheduled_scan.py`로 연결된다. 예약 지시문의 기존 명령을 바꾸지 않아도 최초 실행 시 호환 모델/규칙을 자동 생성하고 모델은 7일, 규칙은 30일마다 갱신한다. Git checkout 시각이 아니라 저장된 학습 시각으로 판단한다. `--prepare`는 학습만 하며 발송하지 않고, `--check`는 준비 상태만 확인한다. 학습 실패 시 불완전한 결과를 발행하지 않는다. 모델이 없거나
호환되지 않으면 기술점수 관찰 목록만 출력하며 엘리트픽/신규 비중을 추천하지 않는다.
이번 코드 수정은 과거 성과가 개선됐다는 실증 결과가 아니다.

## 거래일과 정기 실행

- `America/New_York` 거래소 달력으로 휴장일, 조기 마감, 서머타임을 처리한다.
- 마감 후 30분이 지난 마지막 세션만 사용한다. 실행 시각(UTC)과 시세 기준일을
  별도 저장한다. 종목별 최신 일봉이 기준일과 다르거나 불완전하면 제외 사유를 남긴다.
- 기존 스케줄러가 기존 한국시간 **화~토 07:00**에 `python scheduled_scan.py ALL`을 실행하도록
  설정하면 서머타임과 표준시간 모두 정규장 마감 후 실행된다. 이 저장소가 외부
  스케줄러를 설치하거나 변경하지는 않는다. 거래소 기준 마감+30분 실행도 가능하다.
- 같은 거래일의 저장된 리포트가 있으면 다시 발송하지 않는다. 휴일에도 같은 결과를
  중복 발송하지 않는다. 후보가 없는 날에도 리포트와 성과 갱신을 수행한다.
- 과거 날짜를 지정한 운영 스캔은 금지한다. 현재 재무/실적 일정/모델/통계를 과거에
  적용하면 미래 정보가 섞이기 때문이다. 과거 비교는 당시 저장한 후보 스냅샷을 사용한다.
- 이메일 설정은 로컬 `email_config.json`에 보관하며 Git에 포함하지 않는다.

## 확률과 성과의 구분

`prob`는 **신호 종가 대비 +10% 고가 터치 확률**이다. 매매 수익 확률이 아니다.
`combined`는 기술점수와 확률을 혼합한 순위 점수이며 확률이 아니다.

선택적으로 매매 목표를 별도 학습할 수 있다:

```sh
python surge_model.py train-trade
```

이는 다음 시가 진입 후 손절·D+3 정리·기한 종료보다 먼저 익절에 도달하는
`trade_target` 라벨을 학습해 `trade_model.pkl`에 저장한다. 스캔 JSON의
`trade_target_prob`로 별도 표시하며 순위/매수 게이트에는 자동 반영하지 않는다.
별도의 미래 구간 성과 비교를 거친 뒤 채택해야 한다.

기본 모의 체결 규칙:

- 다음 거래일 시가 + 슬리피지로 진입한다. 목표/손절은 **체결가**로 다시 계산한다.
- +12% 지정가 익절, 3×ATR 손절(7~15%), 최대 20거래일 보유.
- 손절가 아래로 갭 하락하면 시가에서 슬리피지를 차감한 가격으로 청산한다.
- 한 일봉에서 목표와 손절이 동시에 닿으면 손절을 먼저 처리한다. 시가가 목표 위면
  목표 주문이 시가에 먼저 실행 가능한 것으로 처리하되 유리한 가격 개선은 계산하지 않는다.
- 보유 3일째 종가가 `-max(4%, 1.5×ATR)` 이하이면 다음 거래일 시가에 청산한다.
- 비용 가정: 편도 수수료 5bp, 시장가 슬리피지 10bp. 실제 브로커 비용을 확인해
  `execution.policy()`를 변경하고 버전을 올린다. 이는 실거래 체결 내역이 아니다.
- 리포트 가격표는 신호 종가 기준 참고값이다. 실제 매수 후 체결가에 맞춰 주문을
  다시 계산해야 한다. 손절폭으로 계산한 위험 한도는 갭 손실을 보장하지 않는다.

## 검증과 기록

학습/보정/임계값 선택을 날짜 단위로 분리하고 각 경계에 목표 기간만큼 퍼지한다.
GBM의 임의 조기 종료 검증은 끈다. 외부 워크포워드는 별도 평가다.
목표 정밀도를 충족하는 임계값이 없으면 1.01로 설정해 추천하지 않는다.
패턴의 홀드아웃은 규칙 선택용이며, 최종 성능은 이후 고정 규칙으로 검증해야 한다.

- 과거 `predictions/*.jsonl`, `tracker_stats.json`은 변경하지 않는다.
- 새 기록은 `predictions/v3/`, 통계는 `tracker_stats_v3.json`, `quiet_stats_v3.json`.
- 각 예측은 거래일, 실행 시각, 모델 해시, 체결 규칙을 보존한다. 동일 거래일 예측을
  덮어쓰지 않으며 완료된 평가는 설정 변경만으로 다시 계산하지 않는다.
- 분할/배당으로 수정주가 기준이 변하면 저장 당시 종가로 평가 시세를 재기준화한다.
  필요한 거래일이 빠져 있으면 평가를 보류한다.
- 유동성 통과 전체 후보를 `reports/candidates/<거래일>.json`에 저장한다. 기술점수
  게이트 미달 종목도 모델 평가를 수행한다. 스냅샷은 첫 생성 후 덮어쓰지 않는다.
- 모든 데이터와 모델은 생존 종목 중심 목록의 편향이 있다. 순방향 기록도 시장/업종
  동조화와 표본 부족을 고려해야 한다. 최근 비용 차감 평균 수익이 비양수이고 표본이
  30건 이상이면 신규 배분을 중단한다. 10일 성과 기반 감시에는 지연이 있다.

## 계좌 전체 비중

`portfolio_state.example.json`을 참고해 **실제 확인한** 현황을
`portfolio_state.json`에 작성한다. 예시 티커를 실제 보유로 사용하지 않는다.

- `as_of_session`: 스캔 기준 미국 거래일.
- `positions`: 실제 보유 + 예약할 미체결 매수 주문. `ticker`, 총자산 대비 `weight`,
  위험 계산용 `stop_pct`를 기록한다. 같은 티커는 합산한다.
- 실제 보유/주문이 없다면 `positions: []`를 명시한다.
- 파일 없음, 오래된 기준일, 잘못된 값이면 비중 제안을 보류한다.
- 기존 보유를 포함해 최대 4종목/40% 투입과 계획 손절 위험 한도를 적용한다.
  기존 종목 중복 매수와 고상관 후보를 제외한다. 기존 보유를 자동 매도하지 않는다.
- 파일은 Git에서 제외된다. 브로커 계좌와 자동 동기화되지 않으므로 실행 전 갱신해야 한다.

## 네 전략의 동일 조건 비교

```sh
python strategy_compare.py --bars data/bars --output reports/comparison.json
```

`data/bars/TICKER.csv`에 `Date,Open,High,Low,Close,Volume` 열을 제공한다.
날짜는 미국 거래일, 가격은 같은 수정주가 기준이어야 한다. 비교기는 네트워크 요청이나
이메일을 실행하지 않는다. 당시 저장한 후보만 사용해 모델 단독/기술점수 단독/혼합/
혼합+엘리트를 비교한다. 혼합+엘리트의 임계값은 스냅샷의 모델 임계값이며 운영 중
tracker 게이트와 국면 배율은 재현하지 않는 별도 비교 실험이다.

다음 시가 진입, 비용, 기존 포지션, 현금, 4종목/40% 한도, 과거 수익률 상관을 반영해
계좌 순수익과 최대 낙폭을 계산한다. 같은 날 청산금을 그날 시가 매수에 재사용하지 않는다.
어떤 후보라도 평가 기간 시세가 불완전하면 그 스캔 전체를 비교에서 제외하고 사유를 남긴다.
새 스냅샷과 충분한 미래 시세가 없으면 `insufficient_data`를 반환한다.
추가 지표나 필터는 이 비교와 이후 미사용 기간 검증을 통과한 뒤 적용한다.
